# Cartograph V3 — 地图核心

V3 当前只实现一件事：**把 Minecraft 存档中已经完整生成的地表快速画成地图。**

## 第一阶段允许的功能

- M 快捷键打开/关闭大地图。
- 左键拖动画布。
- 滚轮缩放。
- 当前已经加载的区块：直接读取 Minecraft 内存中的真实地表。
- 当前未加载但存档中已经 FULL 的区块：直接读取对应 .mca，不加载/生成 Minecraft 区块。
- 每个 16×16 区块独立返回并立即绘制，不存在“地图页”或整页等待。
- 已取得地表按世界 UUID + 维度 + 区块坐标持久化；关闭地图、退出游戏、重新启动后直接从本地恢复，不重新请求服务端。

## 第一阶段明确禁止

- 地图册物品。
- 地图纸、墨水、颜料、解锁、扣费。
- 玩家位置/指南针/定位按钮。
- 小地图。
- 标点、区域、道路/铁路图层。
- 多种地图风格。
- 任何旧 V1/V2 地图运行时或 fallback。

## 数据原则

地图原始数据只由两种真实来源产生：

1. 已在 Minecraft 内存中的 LevelChunk；
2. 存档 .mca 中状态为 full / minecraft:full 的区块。

未完整生成的区块保持空白，禁止按 seed 预测或伪造。

V3 独立源码位于 v3/neoforge-1.21.1，包名 com.wanstu.cartographv3。
构建任务 verifyV3Isolation 会拒绝任何旧 com.wanstu.cartograph 运行时类或 import。

## 已验证

- 首次打开：89ms 出第一块，93ms 到 128 块，468ms 到 192 块。
- 持久缓存：重启客户端后 0 个新的地形网络包，192 块本地恢复约 39ms；服务端 .mca 读取计数不增加。

## 大范围与新生成区块验收

- 大范围历史存档视野：服务端逐区块检查得到 408 个 FULL，客户端缓存 408/408，缺失 0。
- 测试新区块 (80,-80) 在传送前对应 region 文件不存在。
- 原版传送后生成该区域，打开地图 89ms 收到第一块，第一块就是 (80,-80)；服务端来源为 V3_LOADED_DIRECT_READ。
- 93ms 已收到 128 个新生成区块。
- 强制保存后，该视野 187 个位置中 143 个为 FULL；客户端地图 143/143，缺失 0。
- 拖动与缩放不会清空已取得的地图块。


## 缓存正确性与单区块变更验收

- 每次打开地图都会对当前可见的本地缓存做一次内容指纹校验。
- 本地缓存先显示；服务端确认未变化时只返回 VALID，不重传 256 像素。
- 同一次游戏中关闭地图再打开，当前可见缓存会重新校验一次。
- QA 中在地图关闭期间执行原版命令：/setblock 1278 250 -1307 minecraft:diamond_block。
- 重新打开后日志只出现 1 个完整地图块更新：chunk 79,-82。
- 目标缓存 SHA256：633D744E250B83613D186215C096E51F95E3755B7B1F2A51EA329AD172A5B876 -> 4CA9BEC20108725D64922316B5BBAADC114AA1807A019CCBA5A5675457CE0706。
- 左邻 78,-82 SHA256 保持 D57F3E200AA111A8E54E551FB03533660842D765F33863270A7D9B3068AD8923。
- 右邻 80,-82 SHA256 保持 7BE1EA219744C6499DDA3D647D4B70267C21701627CD7EB622D4E69438D2F569。


## 实时地表更新验收

- 已被地图请求且当前仍由 Minecraft 加载的区块，每 tick 重新采样 16×16 地表指纹；未变化时不发送网络数据。
- QA 将 chunk (0,0) 的 (8,300,8) 从绿宝石块改为钻石块，15ms 后服务端只推送一次 chunk (0,0)。
- 客户端 0_0.ctv3 的 SHA 随真实地表变化而变化；两个无关缓存文件 SHA 保持不变。
- 继续静置 15 秒后 V3_LIVE_PUSH 总数仍为 1，证明自动保存不会造成同 fingerprint 重复推送。
- ChunkDataEvent.Save 只标记磁盘副本 stale，不再销毁内存指纹；区块以后卸载并重新从 .mca 请求时才强制绕过旧缓存。
