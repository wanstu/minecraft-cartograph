# Cartograph 世界数据与双覆盖蒙层契约

## 核心要求（2026-11-09 用户确认）

**真实地表数据与制图材料完全解耦。**

世界地表索引是预先获取/保持的真实已生成 FULL 区块信息；**不足墨水或染料并不阻止底层采样，也不触发重新加载或重新绘图**。是否可见以及是否彩色由两套独立的空间覆盖蒙层决定：

1. **测绘显示蒙层（survey visibility mask）**：未揭开的单元是空白，已揭开才能显示其真实地貌。
2. **彩色蒙层（colorization mask）**：对已经可见的单元，未解开的去色层显示黑白/灰阶地图，已解开则显示当前风格的彩色地图。

显示真值表：

| 测绘可见 | 已彩色 | 绘制结果 |
|---|---|---|
| 否 | 否 | 空白 |
| 否 | 是 | 空白（隐藏优先） |
| 是 | 否 | 无色地图 |
| 是 | 是 | 彩色地图 |

## 面积与资源单位

- 两个蒙层**有独立覆盖单元面积**（以世界方块坐标对齐，按维度和地图册隔离，不随缩放、旋转或风格切换变化）。每单位材料解锁多少覆盖单元由该材料投入/消耗参数决定。
- 不要假设固定等于原版地图页、chunk 或 GPU tile；面积粒度应明确并作为稳定配置/版本兼容参数。**原型样例的面积大小不代表最终游戏规则**。
- 投入倍率与消耗倍率相互独立，**都不允许为 0**；最小 0.1，最大 10.0。默认应非常宽松，让采集与上色只是附带趣味，而不是负担。
- 三个独立的永久开关：**永久测绘墨水、永久彩色、永久发光墨水**，不能用“消耗倍率设为 0”来代替。首次投入墨囊/齐备三色染料/投入发光墨囊的解锁门槛仍在。
- 在非永久模式下，红黄蓝三色染料每组成套投入补充彩色覆盖额度；永久模式下首次齐备即可持续显示彩色。
- 已揭开的蒙层状态必须持久化。后续余额不足不会让**已显示**区域重新变空白或褪色；新材料只用于继续覆盖未揭开的单元。
- 不需重采样：投入材料或切换永久选项只改蒙层状态/额度，最终显示可由 GPU/Canvas 透明合成或着色器处理。

## 数据与安全边界

- 底层 `WorldSurfaceIndex` 保存真实世界地表，**不依赖玩家是否有墨水**；新数据到达时可以先进入索引，延后决定是否可见。
- 服务端应负责蒙层授权、材料扣除和蒙层持久化；客户端只拿允许显示的内容，避免客户端直接移除隐藏蒙层来窥视未揭开的地图。显示蒙层不能当作“仅客户端遮挡”安全边界。
- 三种风格的底图均复用相同世界地表快照和相同蒙层。不应每次补墨水重新读取 MCA NBT，也不应每次补颜料重新生成风格纹理。
- 每种风格可以维护一次预生成的彩色/灰阶渲染结果，运行时使用覆盖蒙层进行 GPU 复合，控制缓存淘汰和增量更新。
- 资源耗尽时允许地表快照继续变化、到达并缓存；用户材料再次到位时仅更新显示授权。

## 必验收案例

1. 未投入材料但世界索引里有 FULL 区块：地图空白，索引不因墨水不足停止读取。
2. 只投入墨囊：地表变为无色图，覆盖面积与倍率一致。
3. 再投入红黄蓝染料：已有无色区域变彩色，**不会重新读取世界**。
4. 先补染料但没有墨囊：仍显示空白；先前彩色额度可用于后续揭开的区域。
5. 墨水/颜料余额刚好到 0：已覆盖区不退回空白/灰阶；未覆盖区仍封闭。
6. 之后再投入材料：仅增量改变蒙层，不改变已覆盖区，也不重复收费。
7. 切换像素/写实/手绘，放大/缩小，移动小地图：两种蒙层在相同方块坐标下保持一致。
8. 分维度、分地图册和边缘方块/边界、并发扣费、存档恢复，均不串账、不重复扣费。
9. 倍率最小 0.1 最大 10，禁止 0；永久开关相互独立，首次解锁门槛生效。
10. 服务器侧未授权的空间单元不因客户端缓存或地图切换泄露底层已预载内容。

**该文件是架构和验收要求，并不代表上述原生运行逻辑已经全部实现。** 现有 AtlasWorldData.recordSurface / SurveyLedger 的收费-绘图耦合需要下一阶段专门重构，不能以“旧代码能跑”作为验收通过。
