# Cartograph 2026-11-10 实测反馈修复

## 问题与根因

1. 区域名称、备注、颜色值和标点编辑框看不见、无法正常输入：上一版把弹窗整体提升到 Z=300，原生 EditBox 却在弹窗退栈后按 Z=0 绘制，控件被不透明弹窗挡住。
2. 区域、标点点保存立刻关闭且服务端拒绝就丢输入：保存原来是先关弹窗后等回复。
3. 地图册资源页底部多余的扩页按钮：上一版只删除右下角定位按钮，错过了用户用红框指定的资源页扩页按钮。
4. 空地图点击看不到反馈：原来 toast 漂浮在弹窗之外，材料页没有本地等待状态也没有具体资源余额消息。
5. 大地图一块一块出现，间隔很长：每个128²瓦片由64个完整16²区块组成，按序从已经加载的区块或磁盘保存的 FULL NBT 读取，单客户端同一时刻一张瓦片。上一版必须读完64个区块才一次性发整张贴图，加载了几十个瓦片必然有明显延迟；不是材料冷却。

## 已改

- 将 `super.render` 的原生可编辑控件放进弹窗的 Z=300 绘制域，避免被弹窗遮挡；默认聚焦名称输入；色板选中时有明显轮廓。
- 编辑标点/区域在服务端成功确认后关闭，失败保留字段、允许修正重试；超过10秒未收到确认时提示超时。
- 资源面板移除多余的「使用纸值扩充一页」及底下说明；仅保留查看余额和进入材料槽；扩页操作移至材料槽底部。
- 材料槽直接显示“正在提交…”和服务端确认/失败原因；空地图成功消息包含最新地图纸值，没材料时明确指出缺哪种物品。
- 服务端地表扫描分8、32、64区块实际快照增量绘制（之前只到64才返回）；每tick最多16区块且受约4ms时间预算约束，异步预读不加载/生成世界。
- 完整页才触发邻瓦片地形光影重建，避免一个页面分阶段时反复重算相邻纹理。
- 添加超10秒阻塞日志，包含当前页坐标、扫描进度、磁盘队列和后台完成计数；每30秒输出聚合缓存读取指标，便于下一次现场诊断。

## 测试与边界

- `scripts/verify-native-dialog-and-survey.py` 通过，保护Z层、按钮位置、服务端确认处理和分阶段地表响应。
- `scripts/verify-world-index.py`、`scripts/verify-common.sh`、NeoForge离线构建和JAR结构校验通过。
- **未声称通过游戏内 GUI 点击、图像画质或加载耗时的实测验收**。实际性能仍取决于已生成世界大小、NBT磁盘读取和客户端帧率，需要对新 JAR 进行一次现场复测。
- 模组不会凭空生成未存在的区块，也不会读取云层。用户场景地图读几十个瓦片需要扫描几十乘64个真实区块，本轮减少不必要的整页等待，没有取消真实数据成本。
