# Cartograph 地图 UI、测绘与响应修复记录

日期：2026-11-09。目标：Minecraft 1.21.1 NeoForge。

## 本次针对三个实机反馈

### 1. 必须遵循 HTML 高保真原型

- 原型：`preview/cartograph-fullscreen-hifi.html`。
- 游戏内地图继续占满整个窗口。工具栏、右侧资源/标点/图层/信息浮窗、标点/设置弹窗都是独立图层；无固定侧栏和底部边框。
- 之前界面被 Minecraft GUI Scale（例如 3 倍）再次放大，导致工具栏、浮窗过大并被窗口裁剪。
- 现在仅游戏操作界面使用 `chromeScale=1.55 / Minecraft GUI scale`；世界地图像素本身独立绘制。GUI 1–4 档、1280/1686/1920 像素宽的目标尺寸均由 CI 静态回归测试检查：
  - HTML 原型的右浮窗宽度 338px → 游戏内设计 218×1.55≈338px；
  - 原型对话框约 495px → 游戏内设计 320×1.55≈496px；
  - 工具栏使用类似原型的细线图标，而不是被 GUI 级数放大的物品贴图；
  - 地图初始物理缩放为每方块约 2.35 个设备像素，鼠标点击/拖动/滚轮与弹窗输入使用相匹配的坐标变换。
- 原型的小型悬浮坐标状态条保留为可见状态提示，**不恢复整屏底部框**。

### 2. 性能及无反馈

- 修复服务端原先“标称每 tick 两个、实际单人只处理一个区块”的循环；现在采用两次采样预算和轮转处理。
- 测绘第 8、32、64 个区块时分批向客户端返回阶段性页面；不用等全部 64 个区块处理完才显示地图。
- 只在服务端真正完成全页时结束客户端 `inFlight`；中间进度响应会续约，不在请求被拒绝时无声等待。
- 从实际已保存的 `.mca` 区域读取时缓存 FULL 地表样本；区域文件保存时间或大小变化就使缓存失效。正在内存中完整加载的区块不使用此缓存，因此建筑修改会重新采样。
- 显示图层切换每个客户端 tick 最多重建 2 个贴图；空白/无权限页面不申请 GPU 贴图；黑白图像使用 O(128²) 的5×5 邻域多数判定，仍只有深浅两色，不会凭空绘出未知地形。
- 导出原版地图曾在单次服务器操作中读取 64 个区块，改为独立两区块/tick 的任务，结束后才扣 1 张空地图。
- 投入材料、指南针、增删改标点、服务器设置、拓印地图都接收**服务端确认**信息，包括失败原因。操作请求发出时不能显示虚假的“保存成功”。

### 3. 旧区块、新区块看不到

- 曾经用 `LevelChunk.getPersistedStatus()` 拦截实际已加载的完整新区块。现在 `getChunkNow` 已返回 `LevelChunk` 的区块直接读取；尚未加载但已保存且 NBT 状态 FULL 的旧区块才从 `.mca` 读取。
- 在 dadm 实际世界 `cartograph_hifi_smoke` 中，`(0,1),(1,2),(2,3)` 三个真实 `minecraft:full` 区块分别用 Minecraft NBT 解码及游戏内地表采样双重验证通过。状态仅 `minecraft:biomes` 或 `minecraft:structure_starts` 的样本按要求保持空白；这是未完整生成，不属于合法可绘数据。
- 服务端数据包现在包含实际处理数量（最多 64）、真实 FULL 数、已缴墨水测绘数、是否完成、地图册锚点与页数。地图界面会显示“测绘中”“无 FULL 区块”“缺少墨囊”“墨水不足”“未扩充地图页”的不同提示。
- **保留既定地图容量规则**：新地图册只有 1 张 128×128 方块页；工作台放入 `地图册 + 空地图` 才会购买新页，按现有锚点螺旋向周围扩充。新页以外的世界即使真实已生成，暂时仍不显示；这是容量限制，而不是随意猜测。实际完整生成状态、墨囊与地图页都必须满足，才能测绘。0 倍消耗不会免除首次装入墨囊。
- 服务端对“发现 FULL 区块但一个也没画”增加有频率限制的实际日志，包含本页 FULL 数、墨囊是否已投入、余额、每块成本和地图容量。可用 `cartograph.survey` 在实际日志中查找。

## 验证记录

- `bash scripts/verify-common.sh`：通过，包含支付账本、页边界和黑白降噪测试。
- `python3 scripts/verify-ui-layout.py`：通过，包含 1686×895、不同 GUI Scale 下浮窗/弹窗尺寸、控件输入坐标、270–600 虚拟高的重叠检查。
- `cd java/adapters/1.21.1-neoforge && ./gradlew --offline check build`：已在 dadm 通过。
- 使用实际 NeoForge 开发服务器和保存世界验证地表采样器：FULL 样本读取通过、不完整区块保持空白。
- **这些不等于玩家客户端视觉和操作验收。** 新 JAR 仍在 `development` Prerelease，正式版开关 `release_ready=false`。

## 游戏内验收顺序

1. 替换旧 JAR，重启客户端；截图对照 HTML：大地图占满全屏，工具栏约 60px 高，右资源窗约 338px 宽且不溢出，不存在固定底栏。测试 GUI Scale 2、3、4。
2. 使用已经生成并保存过的世界、带空地图制作的地图册。注意**原始地图页只有 128×128 方块**。先往资源窗投入墨囊，然后查看对应已生成区块；状态会显示 `64` 区块中的真实 FULL 数与已绘制数。
3. 在当前已购买的地图页内新生成/修改地形，重新打开地图或等候定期刷新：新完整区块应被绘制，旧区块变化不再扣墨。
4. 将地图册和更多空地图放普通工作台扩页，再检查新覆盖页中已保存的旧区块，仍不显示未 FULL 的区块。
5. 分别测试投入三原色、指南针装取、增删改标点、图层开关和地图拓印；每次操作必须得到明确的服务端确认或失败提示。多次切换图层不应长期卡死。
