# Minecraft Cartograph 0.1.2：已生成区块与地图纸授权分离

## 复现的原因

玩家已在 X=1733 Z=9971 附近，但大地图坐标 X=-18 Z=76，仅显示起始页。旧版本第一张纸绑定初始锚点，单张纸仅覆盖该处 512×512。移动几千方块后，大地图又自动把视角拉回原始锚点。旧版本扩页则继续从原始锚点的螺旋位置追加，无法在远距离的新地形铺纸。

已缓存瓦片数不等于位于当前视野内或已获得纸张、墨水授权的区域。不能凭截图认定墨水不足。

## 本次修复

- 底层真实地形仍由世界区块生成、加载、保存及真实变化更新，和玩家有没有地图物品无关。
- 第一层纸张分为旧螺旋页（完整保留已存档范围）与任意位置的新纸张；新纸张可铺在大地图的当前中心，保存在世界 SavedData。
- 墨水与颜料两层授权保持不变，纸张扩页不产生任何绘制权限、不改变扣费设置、不生成世界区块。
- 新纸张位置由服务端通过 paper_coverage 协议同步客户端，补纸后旧无纸占位图会清除并重新从世界已生成地表请求。
- 打开地图及 Home 键保持玩家位置，若未铺纸显示明确材料引导。
- 在地图册面板及设置-缓存与性能均增加生成当前视野地图按钮；只查询已经生成的 FULL 区块。
- 原刷新已测绘区域改为高级旧地图校验，明确不负责生成地图。
- 掉落及拾回地图册保留已有 GPU/CPU 纹理，同时对再次可见页做一次校验，防止错过掉落期间的世界变化。
- 新旧客户端网络版本提升到 17，构建模组版本为 0.1.2。

## 验收

verifyPaperCoverage 覆盖远距离 X1733/Z9971 纸张追加、原始纸张不丢失、NBT 重载、旧 0.1.1 存档兼容及维度隔离。其它缓存、材料权限和色彩增量测试不应回退。

不要替换用户存档，不使用 eadm。完整游戏实机 UI 手动操作需后续独立验收。
