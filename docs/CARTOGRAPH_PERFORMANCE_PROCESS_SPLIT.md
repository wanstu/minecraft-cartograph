# Cartograph 性能修复与独立处理进程边界

## 本轮证据

2026-11-23 用户反馈：移动几步会卡，原地不动也会短间隔卡顿。
EADM 的 GeoWorld-Civilization-1.21.1 日志在 20:58—20:59 记录了：

- 客户端 `cached=262046`，后台持续 `V3_FULL_DIRECT_READ` 和 `V3_MAP_CACHE_VALID`。
- 服务端多次落后 4,755—7,580 ms。
- 当前源码仍有全区块同步采样、客户端请求同步读缓存、关闭地图后实时观察继续运行的路径。
- 原生图集恢复和索引建立也存在主线程文件访问；新建图集原本不受每帧绘制预算约束。

这些记录证明存在过量缓存恢复和持续工作，尚不能把每一次卡顿全部归因于 GC。

## 当前修复

- 区分世界采集和前端可见状态。关闭最后一个前端清空过期可视请求、撤销实时观察，保留后台采集。
- 再次打开前端创建新的校验会话，防止关闭期间发生地形变化后旧缓存永远不校验。
- 已加载区块逐列采样，共享约 1 ms/tick 的时间预算和 512 列/tick 的操作上限。单列耗时仍是最小不可分割开销。
- 磁盘事实缓存、图集及图集目录索引异步读取，过期恢复任务可以取消。
- 客户端和服务端地形事实、服务端结构缓存设置容量上限，客户端淘汰不等同于区块不存在。
- 远景原始事实请求沿用已有的范围上限。原生前端从已知地形和已存图集选取区域，不遍历空白视野。
- 图集异步恢复最多 4 个在途任务，每帧最多新建一个纹理图集。
- MCA 区域位置表一次读取 4 KiB，替代 1,024 次不带缓冲的 readInt。

## 独立进程值得实施的部分

独立进程能隔离地图的堆、缓存生命周期和垃圾回收，也能在 MC 退出后继续处理已经获取的数据。
CPU、磁盘和 GPU 仍是同一台机器的资源，所以进程隔离必须配合并发上限、有限队列和优先级。

| MC 模组内 | 独立地图处理进程 |
| --- | --- |
| 在所属游戏线程分批采集不可变的地表快照 | 事实索引、压缩、持久化与恢复 |
| 导出资源包外观、注册表与群系着色信息 | 手绘语义、跨区块地貌处理 |
| 地图交互、少量可见纹理上传 | 远景 LOD、图集生成、不同风格缓存 |
| 提交变更和接收处理完成通知 | 合并重复任务、续跑、后台处理进度 |

现有 `CartographBackendApi` 可继续作为原生和 Web 前端的边界，后端逐步替换为进程客户端。
不把原生地图界面改成另一套 UI。

### 必须先解除的耦合

`SatelliteSurfaceRenderer` 仍直接使用 Minecraft 单例、BlockState、群系注册表、资源模型和资源包纹理。
`HandDrawnMapData.from` 也会进入该卫星着色路径。
因此不能只把整个现有类放进另一个进程；需要先导出不可变的外观描述和语义事实，使处理核心不依赖 MC 类。

协议至少携带：世界、维度、区块坐标、事实版本、资源包/外观签名、绘图方式/风格、任务版本。
处理结果只有与当前目标签名、事实依赖和任务版本一致时才能应用。
不能混用其他风格的旧图；不预测 seed，不绘制未经真实生成/获取的地形，不显示地下。

### 建议顺序

1. 先完成当前卡顿修复和游戏回归，建立关闭地图静止、移动探索、打开地图、远景缩放的帧时间基线。
2. 抽出纯数据处理核心和外观快照契约，先保持算法与呈现一致。
3. 首版采用单个独立 Java worker，复用现有算法；是否改为 Go/Rust 由测量结果决定。
4. 使用本机通信和有界队列，合并同一区块的重复任务。MC 不等待重处理完成，不为每个任务启动进程。
5. 提供启动、停止、进度和资源占用状态。允许后台继续加工已有队列；停止策略应清晰可控。

以上为拆分评估，当前补丁尚未实现独立地图进程。

## 回归命令

普通构建的 `check` 会执行 `verifyV31PerformanceBudget`，验证预算、公平续跑、前端生命周期、协议标记和缓存容量。

NeoForge 1.21.1 的真实游戏地表采样验证：

```sh
cd v3.1/neoforge-1.21.1
./gradlew --no-daemon --max-workers=1 -I ../../scripts/verify-v31-game.gradle runPerformance
```

该命令在隔离的 GameTest 世界中比较分批采样与同步参考结果，覆盖水深、透明方块、树叶与阴影，验证重复请求复用和不强制加载区块。
测试辅助源只由上述显式 init script 加入；普通发行构建不包含辅助类或测试结构。

原生图集 GPU/缓存回归（在测试用图形显示环境运行）：

```sh
cd v3.1/neoforge-1.21.1
./gradlew --no-daemon --max-workers=1 -I ../../scripts/verify-v31-game.gradle runNativePerformance
```

该测试使用隔离开发客户端与合成夹具，检查四个阶段：卫星图、远景缩放、手绘古式切换，以及清空内存事实后仅凭磁盘图集恢复。它用于验证真实纹理创建/上传、风格隔离和队列上限，不代替用户整合包的帧时间实测。

背景资料：[Java 21 G1 回收暂停](https://docs.oracle.com/en/java/javase/21/gctuning/garbage-first-g1-garbage-collector1.html)、[NeoForge 网络任务线程](https://docs.neoforged.net/docs/networking/payload/)。

## 本轮验证结果（2026-11-23）

- Minecraft 1.21.1 / 26.3，NeoForge / Fabric：四个目标的 check、build 均通过，每个目标执行 26 项性能回归检查。
- NeoForge 1.21.1 GameTest：真实区块分批采样与同步参考一致，必需测试通过。
- NeoForge 1.21.1 原生图集测试：四阶段通过，签名隔离、读取队列上限、仅磁盘恢复均通过；隔离的 llvmpipe 客户端记录单次 update 最大约 21.38 ms。这不是用户整合包的 FPS 或延迟结果。
- 四份发行 JAR 均通过元数据/结构校验，并确认不含测试辅助类和夹具。
