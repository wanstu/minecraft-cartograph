# Minecraft Cartograph：三层材料授权与性能优化（2026-11-11）

## 设计结论
三层是逻辑规则，不是三张 GPU 蒙层或三份真实地形数据。
真实世界地形只采集、缓存、增量更新一份。三种授权状态分别为：

- 地图纸/空地图：AtlasState.pages 与 MapSheetCoverage，地图纸页粒度（默认512×512方块，允许设置）；决定拥有哪张页面。
- 墨水：服务器 SurveyLedger.surveyed，16×16区块粒度；决定地图是否显示地形。
- 颜料：服务器 SurveyLedger.colorized，16×16区块粒度；决定已显示地形是否彩色。

无纸：NO_PAPER；有纸无墨：BLANK_PAPER；纸+墨：GRAYSCALE；纸+墨+颜料：COLOR。
颜料授权可以先获得，但不会绕过墨水显现未知地形。服务器扣费/授权和客户端显示缓存相互独立。重绘与更新地形不能改变任何材料余额或已测绘/已彩色状态。

AtlasLayers.compose 为纯逻辑规则；PixelPageTexture.create 在16×16区块粒度先计算授权，然后在一次纹理创建中合成最终图像（复用原有多个风格/缩略图纹理图集）。没有三个独立GPU蒙层、三次绘制或第三份真实地表缓存。

## 本轮 CPU、GPU、I/O 优化
- AtlasScreen 每帧只做一次可见页筛选，像素、对比和地图标注共享结果，避免对1400页CPU缓存反复全量遍历。
- 同一世界切换多个地图册，保留各地图册CPU/GPU缓存；世界/维度切换强制隔离。
- 极小缩放时，每次最多排队64个新磁盘或网络页任务；最多192个待读磁盘键，两个后台读取线程。
- 地图页写入按世界、地图册、维度、页坐标为唯一键合并；2个后台写线程，同键串行，1400页队列上限；超出仅淘汰最旧未开始的**可重新生成的本地显示缓存**。服务器权限账本不受影响。
- 缩放/拖动优先复用已有CPU像素及GPU纹理；实际地形编辑仍按16×16差量更新。材料授权判断不额外扫描世界。
- 保持旧版本存档 NBT 的纸/墨水/颜料授权及扣费格式不变。

## 未解决的限制
旧版客户端Page v5缓存将未染色区域保存为灰阶像素；真实原材质颜色在服务端世界地表缓存中。新增颜料的授权仍可能需要服务端读取局部原始数据；本轮没有改变旧缓存v5格式、擅自下发未授权世界数据。下一阶段可在保持旧缓存兼容的条件下实现色彩局部补丁，避免颜料变更触发整页刷新。

## 测试界限
- verifyLayers：8种权限组合、颜料先于墨水、无重复收费、永久解锁和存档快照。
- verifyCacheStress：30000次模拟压力，4096次真实GZIP页写入、两个世界/四个地图册/1024唯一页键，断言最后一份快照、余额、队列容量正确。
- verifyMapCache：真实磁盘格式、增量补丁、双蒙层、空白页和存档恢复。
- 真正FPS/TPS与多玩家上千页负载需要独立实机测试；不能把这些合成测试称作完整游戏压力验收。
